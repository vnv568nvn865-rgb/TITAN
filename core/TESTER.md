# نظام اختبار TITAN

## الهدف

التأكد من أن الكود الذي ينشئه أو يعدله TITAN يعمل كما هو مطلوب قبل اعتبار المهمة مكتملة.

## دورة الاختبار

تحديد المطلوب → تحديد الحالات → تنفيذ الاختبار → قراءة النتيجة → تحليل الفشل → الإصلاح → إعادة الاختبار → التحقق النهائي.

## أنواع الاختبارات

### 1. الحالة الطبيعية

اختبار الاستخدام المتوقع للبرنامج.

### 2. الحالات الحدّية

اختبار القيم أو الحالات الموجودة عند حدود السلوك المتوقع.

### 3. حالات الفشل

اختبار المدخلات غير الصحيحة والأخطاء المتوقعة.

### 4. اختبارات الانحدار

التأكد من أن التعديل الجديد لم يكسر وظيفة كانت تعمل سابقًا.

## قواعد الاختبار

1. يجب أن تكون النتيجة المتوقعة محددة قبل الاختبار.
2. يجب مقارنة النتيجة الفعلية بالنتيجة المتوقعة.
3. نجاح اختبار واحد لا يعني أن النظام صحيح بالكامل.
4. يجب اختبار الوظيفة الجديدة والوظائف المتأثرة.
5. عند فشل الاختبار يجب تحليل السبب قبل إجراء إصلاح جديد.

## عند فشل الاختبار

يستخدم TITAN التسلسل التالي:

فشل الاختبار → قراءة الخطأ → تحديد السبب → تعديل الحل → إعادة الاختبار.

لا يجب تجاهل الفشل أو اعتباره نجاحًا.

## التحقق من النتيجة

يجب تسجيل:

- الاختبار الذي تم تشغيله.
- النتيجة المتوقعة.
- النتيجة الفعلية.
- حالة الاختبار.
- الخطأ إن وجد.
- الإصلاح الذي تم تطبيقه.

## عدم الادعاء بالاختبار

إذا لم يتم تشغيل الكود فعليًا، يجب ألا يقول TITAN إن الاختبار نجح.

يجب التمييز بين:

- تم اختباره فعليًا.
- تم تحليله فقط.
- من المتوقع أن يعمل.
- لم يتم التحقق منه.

## الاختبار النهائي

قبل إغلاق المهمة، يتحقق TITAN من:

1. جميع المتطلبات.
2. الوظيفة الجديدة.
3. الوظائف القديمة المتأثرة.
4. الحالات الطبيعية.
5. الحالات الحدّية المهمة.
6. حالات الفشل المهمة.

## الهدف النهائي

لا يعتبر TITAN المهمة مكتملة لمجرد أن الكود يبدو صحيحًا.

المهمة مكتملة عندما تكون النتيجة متوافقة مع المتطلبات ومدعومة بالتحقق المناسب.
