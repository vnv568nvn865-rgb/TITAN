# عينة التدريب 009 — إعادة هيكلة الكود

## المعرّف
009_refactoring

## الفئة
إعادة هيكلة الكود

## مستوى الصعوبة
متوسط

## المهمة
يوجد كود Python يعمل بشكل صحيح، لكنه يحتوي على تكرار غير ضروري.

المطلوب إعادة هيكلة الكود لتحسين وضوحه وقابلية صيانته مع الحفاظ على نفس النتائج.

## الكود الأصلي

def print_admin(user):
    print("الاسم:", user["name"])
    print("الدور: Admin")
    print("الحالة:", user["status"])

def print_user(user):
    print("الاسم:", user["name"])
    print("الدور: User")
    print("الحالة:", user["status"])

## التحليل

الدالتان تقومان بنفس العمليات تقريبًا.

الاختلاف الحقيقي هو قيمة الدور فقط.

هذا يعني أن هناك تكرارًا في طريقة عرض البيانات.

يمكن تقليل التكرار بإنشاء دالة واحدة تستقبل المستخدم والدور كمدخلين.

## الخطة

1. تحديد الجزء المتكرر.
2. إنشاء دالة عامة لعرض معلومات المستخدم.
3. تمرير الدور إلى الدالة.
4. إنشاء دوال بسيطة تستدعي الدالة العامة عند الحاجة.
5. التأكد من أن النتائج لم تتغير.

## التنفيذ

def print_user_info(user, role):
    print("الاسم:", user["name"])
    print("الدور:", role)
    print("الحالة:", user["status"])


def print_admin(user):
    print_user_info(user, "Admin")


def print_user(user):
    print_user_info(user, "User")

## التحقق

### اختبار المستخدم الإداري

المدخل:

user = {
    "name": "Ali",
    "status": "Active"
}

print_admin(user)

النتيجة:

الاسم: Ali
الدور: Admin
الحالة: Active

الحالة:

نجاح

### اختبار المستخدم العادي

print_user(user)

النتيجة:

الاسم: Ali
الدور: User
الحالة: Active

الحالة:

نجاح

## النتيجة

تم تقليل تكرار الكود مع الحفاظ على السلوك والنتائج.

## الدروس المستخلصة

1. إعادة الهيكلة لا تعني تغيير وظيفة البرنامج.
2. يجب تحديد التكرار قبل محاولة إزالته.
3. يمكن استخراج الجزء المشترك إلى دالة عامة.
4. يجب اختبار البرنامج بعد إعادة الهيكلة.
5. يجب تفضيل التغيير البسيط الذي يحسن قابلية الصيانة.

## قاعدة مهمة

عند إعادة الهيكلة، يجب الحفاظ على السلوك المتوقع ما لم يكن تغيير السلوك جزءًا من المتطلبات.
